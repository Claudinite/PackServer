# Validation and the pack score

Mirrors [../requirements/validation-pack-score.md](../requirements/validation-pack-score.md).
`IT-VAL-*` covers the pipeline, `IT-SCORE-*` the score. Step numbers are the pipeline's
([../architecture/validation-pipeline.md](../architecture/validation-pipeline.md) §Steps, 1–16).
Archive fixtures are named after the one rule they trip (`with-secret`, `bomb-repetitive`, …) and
are generated by the World, never committed. Two sandboxes exist: the in-process fake, which
performs the bounded extraction of REQ-VAL-022 for real and scripts everything else, and the real
pinned image, exercised by the `sandbox` job with the same fixture names. A test marked
`Runs: sandbox` is proven only there. The prose screen in v1 is the `static-only` `ProseScreen`
implementation and runs for real in-process; the model screen is a later phase, and its tests carry
`Phase: model-screen` and sit outside the v1 burndown (Ariel B6 2026-10-22). Nothing is charged, so
no test here counts a credit.

## Admission and integrity

### IT-VAL-001 Every upload is validated with live progress; the static steps answer first
- **Covers:** REQ-VAL-001
- **Runs:** push
- **Action:** publish by web upload and by trusted publishing; poll the run while the sandbox is scripted to pause at step 8 (load and run); for a third pack, let the static steps pass and hold the prose screen on an install-from-URL finding after the publisher pressed publish.
- **Assert:** each run shows milestones in order (integrity, extraction, manifest, …) before the verdict; the report opens from the dashboard; no archive is downloadable before `published`; the wizard's check step returned the static report before publish, the hold arrived afterwards, and the "Under review" state names the published typical review time.

### IT-VAL-002 Hash mismatch, oversize or non-zstd fail before any sandbox starts
- **Covers:** REQ-VAL-002
- **Runs:** push
- **Action:** three uploads: 3 MB + 1 byte of valid zstd; valid bytes with a wrong declared sha256; a gzip archive.
- **Assert:** each fails at the integrity step with the matching reason; the recorder shows no sandbox invocation and no decompression (the fake sandbox was never called).
- **Contrast:** 3 MB exactly passes integrity.

### IT-VAL-021 A publisher cannot cause unbounded validation spend: 60 runs, 20 dry-runs, a sandbox budget and the $5 line
- **Covers:** REQ-VAL-021
- **Runs:** push
- **Setup:** publisher A, 30 days old with a promoted pack; publisher B, 2 days old with none; the registry-wide sandbox-minute budget and the $5 daily Workers AI line.
- **Action:** A runs 60 validations (publishes, re-runs and dry-runs mixed, 20 of them dry-runs) then one more publish and one more dry-run; B dry-runs 3 times then a 4th; the world spends the sandbox budget and B dry-runs again while A publishes; the fake embedder reports the day's spend reaching $5 and a search query and a publish arrive.
- **Faked:** sandbox (reports minutes), embedder (reports cost), clock.
- **Assert:** A's 61st run and 21st dry-run are refused; B's 4th dry-run is refused; with the budget spent B's dry-run queues behind A's publish, which runs; at the $5 line the search answers from lexical matching with `degraded: true` and the publish's embedding is queued, not dropped; after the clock passes the reset the queued work runs and a repeated query is embedded once and served from the 24-hour cache.

### IT-VAL-017 Ten failed runs a day queue a publisher at one run every 10 minutes
- **Covers:** REQ-VAL-017
- **Runs:** push
- **Action:** a publisher fails 10 runs (`with-secret`) in a day, then submits three valid archives at once while another publisher with 9 failures submits one.
- **Faked:** clock.
- **Assert:** none of the three is refused; they start behind the other publisher's run at most one every 10 minutes (the recorder shows the start times) and the dashboard says the publisher is queued until midnight UTC; the other publisher's run proceeds at once; after midnight UTC the next run starts without delay.

## Archive safety

### IT-VAL-003 Unsafe archives hard-fail
- **Covers:** REQ-VAL-003
- **Runs:** push, sandbox
- **Action:** publish `with-symlink` (escaping link), `with-hardlink-inside` (link inside the tree), `with-traversal`, `bomb-repetitive`, `bomb-entry-count` (5,001 files).
- **Assert:** each fails with `archive.unsafe` or `archive.bomb` and no prose call.

### IT-VAL-020 Archive safety covers links, special entries, collisions and absolute size
- **Covers:** REQ-VAL-020
- **Runs:** push, sandbox
- **Action:** publish `with-absolute-path`, `with-device-entry`, `nested-archive`, `case-collision`, `nfc-nfd-collision`, and an archive of 25 MB unpacked at ratio 10:1.
- **Assert:** each fails with the matching `archive.*` reason; the last fails on absolute size although its ratio is under 100:1.

### IT-VAL-022 Decompression is bounded by produced bytes and stops at the first limit
- **Covers:** REQ-VAL-022
- **Runs:** push, sandbox
- **Action:** feed each limit's boundary fixture: 20 MB + 1 unpacked, a 5 MB + 1 file, 5,001 files, ratio 101:1, depth 33, a 4,097-byte path, a 256-byte component, a 9 MB window.
- **Assert:** each fails with `archive.bomb` or `archive.unsafe`, exactly one limit named, within the memory and time caps; nothing past the limit was written (the fake's and the real sandbox's scratch is empty); the run is not retried.
- **Contrast:** the same fixtures one unit inside each limit extract.

### IT-VAL-023 Every known bomb shape is refused cheaply
- **Covers:** REQ-VAL-023
- **Runs:** push, sandbox
- **Action:** publish each of `bomb-repetitive`, `bomb-many-files`, `bomb-header-lies`, `bomb-huge-window`, `bomb-concatenated-frames`, `bomb-entry-count`, `bomb-deep-nesting`, `nested-archive`, `bomb-quine`, `bomb-sparse-entry`, `bomb-oversized-size-field`, `bomb-unknown-entry-type`, `bomb-skippable-frames`, `bomb-long-path`.
- **Assert:** the first seven fail `archive.bomb`, the rest `archive.unsafe` except `bomb-skippable-frames`, which fails at integrity as `integrity.not_zstd` with no container started; each within bounded time and memory (the `sandbox` run measures); no prose call for any.

### IT-VAL-014 Infrastructure errors retry and cost nothing; extraction failures are final
- **Covers:** REQ-VAL-014
- **Runs:** push
- **Action:** script sandbox B to time out at step 8 twice then succeed; script a crash at step 3.
- **Assert:** the first run reaches `published` after two retries with no quota consumed by the retries; the step-3 crash is `archive.unsafe`, final, with no "Re-run" offered and no prose call; the step-8 retries resume after the sandbox A step's milestone (steps 3 to 6 are one container call, which the recorder shows ran once).
- **Contrast:** a run that times out three times shows verdict `error` and offers "Re-run".

### IT-VAL-045 A sandbox run is bounded in time and a timeout is a verdict
- **Covers:** REQ-VAL-045
- **Runs:** push, sandbox
- **Action:** script a guard that runs 31 s; an extraction that takes 61 s; a run whose total reaches 5 min 1 s; a dry-run of each.
- **Faked:** clock (in-process); real timers in `sandbox`.
- **Assert:** the guard overrun fails `sandbox.timeout`; the extraction overrun fails `archive.unsafe` and is final; the 5-minute overrun fails `sandbox.timeout`; each dry-run answers within 4 minutes of wall-clock or with the timeout verdict.

### IT-VAL-011 Pack content runs only in a fresh, pinned, offline sandbox whose output is untrusted
- **Covers:** REQ-VAL-011
- **Runs:** sandbox
- **Action:** run `with-network-call`, a pack that reads `/proc/self/environ` and writes `/tmp/marker`, and a pack whose check prints a 50 MB report with an extra field; run `gcp` twice.
- **Assert:** the egress attempt is recorded and reaches nothing; the environment holds no secret or binding name; the marker is absent on the next run (fresh container); the oversize or off-schema report is an infrastructure error, not a verdict, and the registry wrote the report, not the sandbox; the image digest in both reports equals the deployed pin; pack code ran only in container B (IT-VAL-051).

### IT-VAL-051 Pack code never runs in the container that produces the served bytes
- **Covers:** REQ-VAL-051
- **Runs:** push, sandbox
- **Action:** publish `with-guard` with sandbox B scripted to return a report claiming a different canonical sha256, an empty capability set and an altered tree; publish a second pack with sandbox B scripted to find a tree hash different from the one container A committed; publish `gcp` normally and read every step's record in order.
- **Faked:** sandbox (in-process); the real image in `sandbox`.
- **Assert:** the first pack promotes the archive container A produced, whose sha256 the validator recorded before B started, and its manifest still lists the guard (nothing B returned changed either); the second pack's load step is refused with a tree-hash mismatch before any pack code ran (the recorder shows no compile, load or run call) and nothing is promoted; for `gcp` the recorder shows container A finish and commit (step 7) before container B starts (step 8), and each step's record is committed before the next starts, so a later step's output cannot rewrite an earlier record (an attempt through the harness is refused).

## The prose screen

In v1 `ProseScreen` is `static-only`: the heuristics of IT-VAL-009 and IT-VAL-035 run as the screen
and hold or fail on their own. The entries marked `Phase: model-screen` describe the model
implementation and run only once a model is confirmed in the Workers AI catalogue and calibrated.

### IT-VAL-012 The prose screen runs last and reads changed files in full; there is no diff mode
- **Covers:** REQ-VAL-012
- **Runs:** push
- **Action:** publish `with-secret` (fails early); publish `gcp@1.0.0`; publish `1.0.1` changing one line of `skills/a/SKILL.md`; publish `1.0.2` changing `README.md` only; a synthetic scope publishes; the admin opens `1.0.1`'s report.
- **Assert:** the ProseScreen port was called only after every cheaper step passed and not at all for the failed pack; `1.0.0` was read in full; `1.0.1`'s call carried `skills/a/SKILL.md` in full and `RULES.md` in full and no other file; `1.0.2`'s carried `README.md` and `RULES.md` in full; no call carried a diff, a partial file or a previous answer; the synthetic publish made no call; the admin's view orders the evidence by the diff.

- **Assert:** every ProseScreen port call carries the pack content inside the run's nonce delimiters with file and line ranges, and no call carries the note, the appeal or a previous report (a contract test on the port rejects any call that does); `with-reviewer-note` is blocked by the static heuristic with the excerpt.
