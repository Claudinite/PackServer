# Validation and the pack score

Mirrors [../requirements/validation-pack-score.md](../requirements/validation-pack-score.md).
`IT-VAL-*` covers the pipeline, `IT-SCORE-*` the score. Archive fixtures are named after the one
rule they trip (`with-secret`, `bomb-repetitive`, …) and are generated by the World, never
committed. Two sandboxes exist: the in-process fake, which performs the bounded extraction of
REQ-VAL-022 for real and scripts everything else, and the real pinned image, exercised by the
`sandbox` job with the same fixture names. A test marked `Runs: sandbox` is proven only there.

## Admission and integrity

### IT-VAL-001 Every upload is validated with live progress
- **Covers:** REQ-VAL-001
- **Runs:** push
- **Action:** publish by web upload, by token and by trusted publishing; poll the run while the sandbox is scripted to pause at step 7.
- **Assert:** each run shows milestones in order (integrity, extraction, manifest, …) before the verdict; the report opens from the dashboard; no archive is downloadable before `published`.

### IT-VAL-002 Hash mismatch, oversize or non-zstd fail before any sandbox starts
- **Covers:** REQ-VAL-002
- **Runs:** push
- **Action:** three uploads: 3 MB + 1 byte of valid zstd; valid bytes with a wrong declared sha256; a gzip archive.
- **Assert:** each fails at the integrity step with the matching reason; the recorder shows no sandbox invocation and no decompression (the fake sandbox was never called); no credit was reserved.
- **Contrast:** 3 MB exactly passes integrity.

### IT-VAL-021 A publisher cannot cause unbounded validation spend
- **Covers:** REQ-VAL-021
- **Runs:** push
- **Setup:** per-publisher daily run cap R, per-publisher prose token budget B and the registry's $5 line, read from configuration.
- **Action:** publisher runs R validations (mix of publishes, re-runs and dry-runs) then one more; a second publisher submits a pack whose text exceeds B; the fake prose screen reports cost reaching $5 for the day and a third publisher submits.
- **Faked:** prose screen (reports token counts and cost), clock.
- **Assert:** the R+1-th run is refused; the over-budget pack waits (`awaiting budget`) with no chunk screened; the third waits too; after the clock passes the reset both resume and are screened in full.

### IT-VAL-017 Ten failed runs a day soft-rate-limit a publisher
- **Covers:** REQ-VAL-017
- **Runs:** push
- **Action:** a publisher fails 10 runs (`with-secret`) in a day, then submits a valid archive; another publisher with 9 failures submits.
- **Assert:** the first publisher's eleventh run is slowed or deferred and the response says so; the second publisher's run proceeds normally.

### IT-VAL-039 A credit is reserved before the prose screen and consumed only at promotion
- **Covers:** REQ-VAL-039
- **Runs:** push
- **Setup:** publisher with 1 credit; a second with 0 credits; a Verified Publisher.
- **Action:** first publishes a new pack whose prose screen holds, then the admin rejects; then publishes a new pack that promotes; the second attempts a new pack; the Verified Publisher publishes a new pack.
- **Assert:** during the hold the balance shows 1 with 1 reserved; after rejection it is 1 and free; after promotion 0; the 0-credit publisher is refused at admission with no upload URL issued and no sandbox call; the Verified Publisher's run reaches the prose screen with no reservation.

## Archive safety

### IT-VAL-003 Unsafe archives hard-fail
- **Covers:** REQ-VAL-003
- **Runs:** push, sandbox
- **Action:** publish `with-symlink` (escaping link), `with-traversal`, `bomb-repetitive`, `bomb-entry-count` (5,001 files).
- **Assert:** each fails with `archive.unsafe` or `archive.bomb`, no credit reserved, no prose call.

### IT-VAL-020 Archive safety covers links, special entries, collisions and absolute size
- **Covers:** REQ-VAL-020
- **Runs:** push, sandbox
- **Action:** publish `with-hardlink`, `with-absolute-path`, `with-device-entry`, `nested-archive`, `case-collision`, `nfc-nfd-collision`, and an archive of 25 MB unpacked at ratio 10:1.
- **Assert:** each fails with the matching `archive.*` reason; the last fails on absolute size although its ratio is under 100:1.

### IT-VAL-022 Decompression is bounded by produced bytes and stops at the first limit
- **Covers:** REQ-VAL-022
- **Runs:** push, sandbox
- **Action:** feed each limit's boundary fixture: 20 MB + 1 unpacked, a 5 MB + 1 file, 5,001 entries, ratio 101:1, depth 33, a 4,097-byte path, a 256-byte component, a 9 MB window.
- **Assert:** each fails with `archive.bomb` or `archive.unsafe`, exactly one limit named, within the memory and time caps; nothing past the limit was written (the fake's and the real sandbox's scratch is empty); the run is not retried.
- **Contrast:** the same fixtures one unit inside each limit extract.

### IT-VAL-023 Every known bomb shape is refused cheaply
- **Covers:** REQ-VAL-023
- **Runs:** push, sandbox
- **Action:** publish each of `bomb-repetitive`, `bomb-many-files`, `bomb-header-lies`, `bomb-huge-window`, `bomb-concatenated-frames`, `bomb-entry-count`, `bomb-deep-nesting`, `nested-archive`, `bomb-quine`, `bomb-sparse-entry`, `bomb-oversized-size-field`, `bomb-unknown-entry-type`, `bomb-skippable-frames`, `bomb-long-path`.
- **Assert:** the first seven fail `archive.bomb`, the rest `archive.unsafe`; each within bounded time and memory (the `sandbox` run measures); no credit reserved and no prose call for any.

### IT-VAL-014 Infrastructure errors retry and cost nothing; extraction failures are final
- **Covers:** REQ-VAL-014
- **Runs:** push
- **Action:** script the sandbox to time out at step 7 twice then succeed; script a crash at step 3; script a crash at step 6 followed by success.
- **Assert:** the first run reaches `published` after two retries with no quota or credit consumed by the retries; the step-3 crash is `archive.unsafe`, final, with no "Re-run" offered; the step-6 crash resumes from step 5's milestone (the recorder shows steps 1–5 ran once).
- **Contrast:** a run that times out three times shows verdict `error` and offers "Re-run".

### IT-VAL-045 A sandbox run is bounded in time and a timeout is a verdict
- **Covers:** REQ-VAL-045
- **Runs:** push, sandbox
- **Action:** script a guard that runs 31 s; an extraction that takes 61 s; a run whose total reaches 5 min 1 s; a dry-run of each.
- **Faked:** clock (in-process); real timers in `sandbox`.
- **Assert:** the guard overrun fails `sandbox.timeout`; the extraction overrun fails `archive.unsafe` and is final; the 5-minute overrun fails `sandbox.timeout`; each dry-run answers within 4 minutes of wall-clock or with the timeout verdict.

### IT-VAL-011 Pack content runs only in a fresh, pinned, offline sandbox whose output is untrusted
- **Covers:** REQ-VAL-011
- **Runs:** sandbox
- **Action:** run `with-network-call`, a pack that reads `/proc/self/environ` and writes `/tmp/marker`, and a pack whose check prints a 50 MB report with an extra field; run `gcp` twice.
- **Assert:** the egress attempt is recorded and reaches nothing; the environment holds no secret or binding name; the marker is absent on the next run (fresh container); the oversize or off-schema report is an infrastructure error, not a verdict, and the registry wrote the report, not the sandbox; the image digest in both reports equals the deployed pin.

## Canonical form, publication and rescans

### IT-VAL-033 The promoted archive is a canonical re-pack that round-trips
- **Covers:** REQ-VAL-033
- **Runs:** push, sandbox
- **Action:** upload a non-canonical archive (unsorted entries, owner metadata, two zstd frames); publish; also run `cn pack canonicalise` offline on the same tree; script a round-trip mismatch for a second pack.
- **Assert:** the served archive differs from the upload, is one frame with sorted plain entries and window ≤ 8 MB, and equals the offline canonical bytes byte for byte; the uploaded bytes remain in staging; the mismatching pack is an infrastructure error and nothing was promoted.

### IT-VAL-041 Promoted versions carry verification facts; the registry applies no policy
- **Covers:** REQ-VAL-041
- **Runs:** push
- **Action:** publish from a Verified org with a domain proof and from a plain scope; revoke the org's Verified status; search and browse with no filters.
- **Assert:** the first index entry has `verified: true`, `verified_domain`, no `verified_github_org`, and the same facts show on its page, its search card and `get_pack`; the plain one has `verified: false` and neither fact; after revocation the scope index is re-signed with `verified: false` and `verified_domain` kept; the plain pack appears in default results and is eligible for the exploration slot, with no warning; a seeded `@claudinite` pack carries `verified: true` and `verified_domain: claudinite.com` with no special path (its scope is verified like any other).

### IT-VAL-018 Live versions are rescanned and a finding quarantines; only a human revokes
- **Covers:** REQ-VAL-018
- **Runs:** push
- **Setup:** three live packs; one's prose cites a domain that the fake DNS will stop resolving.
- **Action:** bump the static rules version; run the weekly domain re-resolution; run the weekly top-1,000 pipeline; the admin clears the quarantine; the admin revokes another version with a security reason.
- **Faked:** DNS, clock.
- **Assert:** every live latest version got a static rescan; the drifted pack is `quarantined` with reason `domain-drift` and its download is held; clearing returns it to `active`; no automatic path produced `revoked`, the admin's action did.

### IT-VAL-043 A dry-run validates without a version or a credit
- **Covers:** REQ-VAL-043
- **Runs:** push
- **Action:** a publisher with 0 credits dry-runs `gcp` and `with-secret`; dry-runs with the prose screen opted in; an anonymous caller and the self-test credential each post a dry-run; a dry-run names another scope's private pack; the publisher reaches 20 runs in the day and submits one more.
- **Assert:** no version exists afterwards and the balance is unchanged; the reports have the same format as a publish report; the opt-in call reached the fake screen; the anonymous and self-test calls are unknown paths; the private-pack dry-run is not found; the 21st run is refused; the dry-run's upload used a single-use credential under its own staging prefix (a replay is refused, IT-PUB-030).

### IT-VAL-044 The offline linter and the registry report the same static findings
- **Covers:** REQ-VAL-044, REQ-CN-011
- **Runs:** nightly
- **Action:** for each content fixture, run `cn lint` offline and a dry-run; also for `gcp` run `cn pack canonicalise` and compare with IT-VAL-033's served bytes.
